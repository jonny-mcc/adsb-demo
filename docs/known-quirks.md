# Known Quirks

Gotchas discovered during development that affect how workflows, alerting, and cases interact. Elastic Stack 9.5 is the supported baseline; older entries remain as migration history.

01. **`lastExecution` on the Workflows API is always `null`** ([elastic/kibana#257744](https://github.com/elastic/kibana/issues/257744)) — after an alert triggers a workflow, querying `GET /api/workflows/<id>` returns `lastExecution: null` even when the workflow has executed successfully. Use the Kibana event log (`.kibana-event-log-*`) or an `elasticsearch.index` canary step to verify execution.
02. **Kibana Cases `_find` `tags` parameter uses OR logic** ([elastic/kibana#257743](https://github.com/elastic/kibana/issues/257743)) — passing `?tags=foo&tags=bar` matches cases with tag `foo` **or** tag `bar`, not both. Use a single unique tag (e.g. `icao24:<value>`) for deduplication queries instead of combining multiple tags.
03. **`.workflows` system connector in alert rules** — the connector works when placed in the rule's `actions` array via the public API, but `group` and `frequency` fields are silently stripped. The public API does not support the `system_actions` field (returns 400). The action still fires correctly on each alert evaluation that meets the threshold.
04. **Workflow output migration from 9.3–9.4** — top-level `outputs` did not reliably populate workflow-tool results on those releases. The 9.5 workflows place inputs under the manual trigger and finish with a top-level `data.set`, so Agent Builder receives the final output directly.
05. **Case custom fields remain `text` or `toggle` in workflow actions** — `cases.createCase` and `cases.updateCase` reject numeric custom-field types. Confidence is therefore stored as the categorical text values `low`, `medium`, or `high`. Use Cases `extended_fields` for field-library values when a configured field requires another storage type.
06. **The enrichment cache was removed for 9.5** — `adsb-enrichment-cache` was a 9.3–9.4 workaround for null workflow outputs. Workflow tools now return their final `data.set` output and agents consume it directly.
07. **`elasticsearch.index` step does not support filters or type-preserving expressions** — the `document` body in an `elasticsearch.index` step only accepts plain `{{ }}` string interpolation. Using `{{ value | json }}` or `${{ expr }}` causes a `Workflow is not valid` error at deploy time. Nested objects interpolated via `{{ }}` are serialised as the string `[object Object]`. **Workaround:** use `elasticsearch.request` with `method: PUT` and `path: "/{index}/_doc/{id}"` instead — its `body` field supports `{{ value | json }}` and handles nested objects correctly when serialised with the `| json` filter.
08. **Workflow execution status can omit step names on older executions** — this affects diagnostics for executions created before the 9.5 workflow migration. Agents no longer poll workflow status for normal tool calls.
09. **`if` conditions fail silently when referencing failed step outputs** — when a step with `on-failure: continue: true` fails (e.g. searching an index that does not exist), its output is `null`. An `if` condition referencing that output (e.g. `${{ steps.X.output.hits.total.value == 0 }}`) does not evaluate as expected — `null` is not `0`, so the condition is false and the branch is skipped. Design workflows to handle the first-run case where dependent resources may not exist yet.
10. **`ai.agent` output is an object** — free-text responses are in `output.message`. When a schema is supplied, typed values are in `output.structured_output`; the hijack workflow routes on those fields rather than parsing Markdown.
11. **Workflows REST API path changed in Kibana 9.4.x** — the single-workflow and run endpoints added a `workflow/` path segment. Old paths (`/api/workflows/{id}`, `/api/workflows/{id}/run`) return 404. Use `/api/workflows/workflow/{id}` and `/api/workflows/workflow/{id}/run`. Execution retrieval path is unchanged: `/api/workflows/executions/{executionId}`. Step listing now uses `/api/workflows/workflow/{workflowId}/executions/steps`.
12. **DLM frozen transitions are capability-gated** — `frozen_after` requires an Enterprise/trial licence and a snapshot repository. The default template uses retention only; setup adds `frozen_after` when `DLM_FROZEN_AFTER` is set and both prerequisites are detected. The legacy ILM policy is no longer part of default setup.
13. **Workflow IDs are source controlled** — setup renders deployment-specific connector, dashboard, endpoint, and space values locally, then uses Kibana's bulk create/overwrite API with stable IDs. A non-force run uses the dry-run conflict check and creates only missing IDs.
14. **HTTP connector secrets are connector-specific** — `secretQueryParams` is supported by the 9.5 `.http` connector, not the classic `.webhook` connector. GNews uses a `.http` connector with encrypted `apikey` query data; the deployed workflow contains only the connector ID, path, and non-secret query fields.
15. **Cases as Data indices are cross-space** — `.cases`, `.cases-activity`, and `.cases-attachments` are restricted analytics indices in 9.5. Read access is not constrained by Kibana space, so queries and dashboards must filter `space_id` and `owner`.
